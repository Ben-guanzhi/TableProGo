# 私有分发包（W15）

本主线**不公开发布**，因此没有 WinGet/Scoop 清单、没有自动发布工作流、没有公开
下载页。这一页只说明：内部怎么出一个包、接收方怎么核对。

## 出一个包

```powershell
powershell -File scripts/release.ps1 -Version 1.1.0
```

脚本做四件事，缺一不可：

1. **先构建前端**——前端是被 `//go:embed` 嵌进二进制的，跳过这步会发出昨天
   的界面。
2. **跑全量测试**——`-SkipTests` 可以跳过，但那意味着你在分发未经测试的构建。
3. **用 `-ldflags` 打进版本号/提交/日期**，然后**读回 `--version` 校验**。
   一个 `--version` 仍报 `dev` 的包是打包 bug，而这只有在接收方写 bug 报告时
   才会暴露，所以脚本当场就失败。
4. **打包并生成校验和**：`dist/tablepro-go-<版本>-<平台>-<架构>.zip` 与
   `dist/SHA256SUMS.txt`，zip 里带 `RELEASE-NOTES.md`（从 `CHANGELOG.md` 截取
   该版本段落）与 `LICENSE`。

产物：

```
dist/
  tablepro-go-1.1.0-windows-amd64.zip   二进制（前端已内嵌）
  SHA256SUMS.txt                         校验和
  RELEASE-NOTES.md                       该版本变更
```

## 分发与核对

只把那个 zip 与 `SHA256SUMS.txt` 交给接收方。接收方核对：

```powershell
Get-FileHash .\tablepro-go-1.1.0-windows-amd64.zip -Algorithm SHA256
```

与 `SHA256SUMS.txt` 里的值逐字符比对。不一致就不要运行。

## 更新检查（可选，默认关闭）

程序**不会自行联网**。若希望「关于」面板能提示新版本，需要自托管一个 JSON：

```json
{"version": "1.2.0", "notes": "修了什么"}
```

并把它的地址配置为更新来源。检查行为：

- 地址为空 → 不联网，面板明确写「未配置」而不是显示一个没验证过的「已是最新」。
- 请求是**裸 GET，无请求体**——不带机器标识、不带连接信息、不带遥测。
- 版本比较是简单的点分数字比较（`1.2` < `1.2.1`，`1.2.0-rc1` 不比 `1.2.0` 新）；
  本地 `dev` 构建会把任何发布版本视为更新。
- 失败（404、非 JSON）会在面板上显示出来，不静默。

## 版本号规则

`主.次.修订`（`^\\d+\\.\\d+\\.\\d+` 校验，不满足脚本直接拒绝）。私有构建建议：

- 修 bug → 修订号 +1
- 加功能 → 次版本号 +1
- 破坏性变更（连接文件格式、配方格式）→ 主版本号 +1，并在 RELEASE-NOTES 里
  写清迁移办法

## 不做的事

- **不发布到 WinGet / Scoop**：那会把包推到公共索引，与「不公开主线」冲突。
- **不做自更新器**：自动替换正在运行的二进制需要代码签名与回滚策略，本计划内
  没有这些资源；只做提示，由人决定何时换。
- **不做遥测**：上面对更新检查的描述就是全部的对外请求。
