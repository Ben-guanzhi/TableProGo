# 服务器模式（W16）

把同一套 HTTP API 暴露给浏览器，前面加一道登录。桌面模式靠"页面在进程内、token 由
宿主注入"划边界；一旦放到网络上，这条边界就没有了，所以服务器模式需要真正的登录。

## 启动

```powershell
# 先在桌面应用里设置口令（服务器模式复用同一个 argon2id 口令存储）
tablepro-go --serve
tablepro-go --serve --listen 0.0.0.0:8765            # 对外监听
tablepro-go --serve --listen 127.0.0.1:8765 --serve-writes   # 允许写接口
```

默认：

| 项 | 默认 | 说明 |
|---|---|---|
| 监听地址 | `127.0.0.1:8765` | 故意是环回：不加思考就把数据库客户端发布到所在网络，不该是默认行为 |
| 写接口 | **关闭** | 只放行只读白名单；备份/传输/行同步/删连接一律 403 |
| 会话 | 内存 | 进程重启即全体登出 |
| 会话超时 | 空闲 30 分钟 / 最长 12 小时 | 数据库客户端的会话不该长期有效 |
| 两步验证 | 未启用 | 可在桌面模式用 `EnrolTOTP` 生成 otpauth URI |

**没有口令就拒绝启动**——一个没人能登录的服务器没有意义，而"忘记设置口令就裸奔"是
最坏的默认。

## 安全模型（以及它的边界）

做对的部分：

- 口令走 `argon2id`（与锁屏同一个存储），错误信息统一为"口令错误"，不区分
  "没设置口令"与"口令错"——后者会向未认证的调用者泄露安装状态。
- 会话 id 32 字节随机、`HttpOnly` + `SameSite=Strict` 的 Cookie；接口不接受桌面模式的
  `X-API-Token`（那个 token 会随页面走，在服务器模式下不再是秘密）。
- **只读白名单是白名单**：新增接口默认被拒，评审时必须显式决定它属于哪一侧。用黑名单
  会让未来每个新接口默认对外发布。
- 写接口即使打开，也仍受 Safe Mode 与各自的确认流程约束。
- 登出、改口令、关停都会清掉会话。

**边界（必须说清）**：这是**单凭据**，没有多用户账号、没有审计日志、也没有内置 TLS。
要放到不受信任网络，前面必须挂反向代理做 TLS，并把它当成"一个有数据库权限的账号"来
对待。它不是多租户服务。

## 两步验证

`internal/totp` 是 RFC 6238 的实现，正确性由 RFC 自身的测试向量钉住（Appendix B 的
6 个时间点 + 截断），另有三条规则决定它是否真的是"第二个因素"：

1. **同一验证码不接受两次**。码在 30 秒窗口内有效，接受两次就把"你有的东西"变成
   "你看到过一次的东西"——肩窥到的一次性码会被重放。已用步号是**进程级**记录，不是
   会话级，否则一个码可以换一个会话再用一次。
2. **skew 是显式的**，默认 ±1 步（±30 秒），够容忍时钟漂移，又不至于让偷到的码长期可用。
3. **恒定时间比较**：6 位码的提前返回是一个约 20 次猜测就能利用的时序口子。

## 与桌面的差异

同一套 API，服务器模式少了这些端点（被只读白名单挡住）：备份、传输、行同步、结构修改、
连接增删改、设置写入。UI 上对应按钮会收到 403 并显示原因。这是有意的：一个"给人看数据"
的部署不该同时握着"能改数据"的手。

## 前端如何知道自己是哪一种

服务器模式**不注入** `__API_PORT__`/`__API_TOKEN__`（注入等于给每个访客一个 API 忽略的
凭据）。前端据此判断：没有端口号 ⇒ 同源部署 ⇒ 请求走同源、浏览器自带会话 Cookie；
有端口号 ⇒ 桌面模式 ⇒ 127.0.0.1 + token 头。任一请求收到 401 且处于同源模式时，显示
登录页，而不是弹一个用户无法处理的错误提示。
